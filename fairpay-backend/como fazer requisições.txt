# Guia de Requisições no Postman para o FairPay

Com base na estrutura do workspace do FairPay, vou explicar como realizar as principais requisições no Postman:

## 1. Criar Usuário (Registro)

**Método**: `POST`  
**URL**: `http://localhost:8090/api/auth/register`  
**Headers**:
```
Content-Type: application/json
```

**Body**:
```json
{
  "name": "João Silva",
  "email": "joao@exemplo.com",
  "password": "senha123",
  "confirmPassword": "senha123"
}
```

**Resposta esperada** (Status 200/201):
```json
{
  "success": true,
  "message": "Usuário registrado com sucesso!",
  "user": {
    "id": 1,
    "name": "João Silva",
    "email": "joao@exemplo.com"
  }
}
```

## 2. Fazer Login

**Método**: `POST`  
**URL**: `http://localhost:8090/api/auth/login`  
**Headers**:
```
Content-Type: application/json
```

**Body**:
```json
{
  "email": "joao@exemplo.com",
  "password": "senha123"
}
```

**Resposta esperada** (Status 200):
```json
{
  "success": true,
  "message": "Login realizado com sucesso!",
  "user": {
    "id": 1,
    "name": "João Silva",
    "email": "joao@exemplo.com"
  },
  "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
  "refreshToken": "1234abcd-5678-90ef..."
}
```

> ⚠️ **Importante**: Salve o `accessToken` para usar em requisições autenticadas!

## 3. Criar Grupo

**Método**: `POST`  
**URL**: `http://localhost:8090/api/groups`  
**Headers**:
```
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9... (token obtido no login)
```

**Body**:
```json
{
  "name": "Viagem para o Rio",
  "description": "Despesas da viagem do final de semana",
  "imageUrl": "https://exemplo.com/imagem.png"
}
```

**Resposta esperada** (Status 201):
```json
{
  "id": 1,
  "name": "Viagem para o Rio",
  "description": "Despesas da viagem do final de semana",
  "imageUrl": "https://exemplo.com/imagem.png",
  "createdAt": "2024-05-16T14:30:00",
  "createdBy": {
    "id": 1,
    "name": "João Silva"
  }
}
```

## 4. Criar Link de Convite

**Método**: `POST`  
**URL**: `http://localhost:8090/api/groups/1/invite-link` (substitua "1" pelo ID do grupo)  
**Headers**:
```
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9... (token do criador do grupo)
```

**Body**:
```json
{
  "expiresInDays": 7
}
```

**Resposta esperada** (Status 200):
```json
{
  "inviteLink": "http://localhost:8090/api/groups/join/a1b2c3d4-5678-90ef",
  "expiresAt": "2024-05-23T14:30:00"
}
```

> ⚠️ **Importante**: Salve o token da URL (a1b2c3d4-5678-90ef) para aceitar o convite!

## 5. Aceitar Convite

**Método**: `GET` (ou `POST` dependendo da implementação)  
**URL**: `http://localhost:8090/api/groups/join/a1b2c3d4-5678-90ef` (token obtido na resposta anterior)  
**Headers**:
```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9... (token de outro usuário)
```

**Resposta esperada** (Status 200):
```json
{
  "message": "Você entrou com sucesso no grupo 'Viagem para o Rio'",
  "group": {
    "id": 1,
    "name": "Viagem para o Rio",
    "description": "Despesas da viagem do final de semana",
    "createdBy": {
      "id": 1,
      "name": "João Silva"
    }
  }
}
```

## 6. Logout

**Método**: `POST`  
**URL**: `http://localhost:8090/api/auth/logout`  
**Headers**:
```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9... (token do usuário)
```

**Resposta esperada** (Status 200):
```json
{
  "success": true,
  "message": "Logout realizado com sucesso!"
}
```

## Dicas para Testes:

1. **Salvar tokens**: No Postman, após o login, você pode salvar o token como variável de ambiente para usar nas requisições seguintes.

2. **Verificar status**: Confirme que está recebendo os códigos de status HTTP corretos (200/201 para sucesso).

3. **Erros comuns**:
   - 401: Token inválido ou expirado
   - 403: Permissões insuficientes 
   - 404: Recurso não encontrado
   - 400: Dados de entrada inválidos

4. **Testar casos negativos**: Tente criar grupos sem autenticação, aceitar convites expirados, etc.
